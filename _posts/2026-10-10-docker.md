Docker dość agresywnie ingeruje w system na którym jest zainstalowany (modyfikację reguł firewalla, automatyczny start nawet gdy nie są uruchamiane kontenery, itd).
Problemy te można wyeliminować poprzez:

1. wyłączenie automatycznego startu:  `disable() { systemctl stop $1; systemctl disable $1; }; disable containerd.service; disable docker.service; disable docker.socket`
2. wyłączenie dodawania reguł iptables i tworzenia własnego bridge'a: `echo '{ "bridge": "none", "iptables": false }' > /etc/docker/daemon.json`

W  `/etc/docker/daemon.json` można także określić inną niż domyślna (`/var/lib/docker`) lokalizację dla danych dockera (obrazy, etc) poprzez wpis `"data-root"` np.: `{ "bridge": "none", "iptables": false, "data-root": "/tmp/docker" }`.

Do uruchamiania i zatrzymywania dockera można skorzystać wtedy np. ze skryptu [docker.sh](/files/docker.sh), który zapewnia także podłączanie bridge'owanej sieci do każdego z kontenerów (w stylu sieci lxc).
Sieć ta nie wykorzystuje żadnego z driverów dockerowych (zamiast tego operuje na natywnych poleceniach linux) aby zapewnić:

* używanie dedykowanych portów bridga systemowego dla każdego z kontenerów
	* bez tworzenia własnego bridga dockerowego
	* z osobnym adresem MAC dla każdego kontenera
* możliwość korzystania z autokonfiguracji IPv6 oraz DHCP dla IPv4
* bezproblemową komunikację systemu hosta z kontenerami (czego nie zapewnia dockerowy `macvlan`)
* zewnętrzną konfigurację sieci w kontenerze (poprzez `nsenter`), dzięki czemu obraz kontener nie musi posiadać narzędzi ip ani klienta dhcp


### przydatne polecenia dockerowe

- uruchamianie w trybie interaktywnym: `docker run -it ubuntu:latest /bin/bash
- listowanie działających kontenerów: `docker ps`
	- interaktywny dostęp do działającego kontenera: `docker exec -it $CONTAINER_ID /bin/bash`
	- kopiowanie plików z/do kontenera: `docker cp` (ścieżka w kontenerze określana jako `CONTAINER_ID:ŚĆIEŻKA`)
	- ubicie kontenera: `docker kill`
- zarządzanie pobranymi obrazami: `docker image`
- usunięcie pozostałości `docker system prune` + `docker volume rm ...`
